# 汽车试驾评价

React + Vite 应用，入口为 `src/App.jsx`。根目录的 `Car_Database` 是旧版源码快照，不是数据库文件，也不参与构建。

## 运行与构建

```sh
npm ci
npm test
npm run dev
npm run build
```

部署时发布 `dist` 目录。本次修复不需要新增后端或环境变量。

## DeepSeek 配置

- 接口地址：`https://api.deepseek.com`。基础地址、带 `/v1` 的基础地址和完整 `/chat/completions` 地址都支持。
- 模型名称：填写账户实际可用的模型。默认示例为 `deepseek-v4-flash`，不会覆盖已保存的模型配置。
- 密钥：填写 API Key；首尾空白和粘贴时附带的 `Bearer` 前缀会自动清理。
- 先点“测试连接”，确认响应后保存。测试会发送一次小型模型请求。

配置保存在浏览器 localStorage，未加密；请求直接发往填写的 API 地址。界面只有实际收到模型响应后才显示“已连接”。

错误会区分 HTTP 状态（例如 401 认证失败、402 余额不足、404 接口或模型不存在、429 限流）、网络错误、超时和返回数据格式错误。不会把所有失败都归为密钥填写错误，也不会重复发送认证失败的请求。请求最长等待 90 秒。

参考：[DeepSeek 首次调用](https://api-docs.deepseek.com/)、[JSON Output](https://api-docs.deepseek.com/guides/json_mode/)。

## 数据库与百分制

应用目前导入、导出的是 CSV，不会直接修改 OneDrive 上的 XLSX。请在 Excel 中将 `Car_Database` 工作表另存为“CSV UTF-8（逗号分隔）”后导入，原 XLSX 继续保留。CSV 不包含工作表格式、图表或公式。

- 旧 `(1-5)` 评分列自动按乘以 20 转为 `(0-100)`，相应分项均分同样换算；原来已是百分制的总分不会再次换算。
- 已是 `(0-100)` 的文件不会重复换算。原有其它列和历史内容保留。
- 新录入、编辑、雷达图和对比均使用百分制，0 分不会变成默认 50 分。
- “保存至数据库”加入本次记录并下载 CSV。同一次试驾再次点击会更新同一条记录；开始新试驾后会新增一条。
- “导出数据库”下载当前全部数据，包括已编辑的历史记录，不额外新增试驾记录。
- 更新记录时重算分项均分。七个分项都具备时按原权重计算总分；缺项时总分与推荐等级留空。原应用仅提供静态、城市、高速、动力、底盘五组录入；数据库中的 NVH、使用和能耗列仍会保留，本次未扩充录入步骤。

## 中文导出修复

导出使用 UTF-8 BOM 和 CRLF 行尾，使 Excel 直接打开时能识别中文。包含逗号、双引号和换行的单元格按 CSV 规则转义；导出从当前数据生成，避免覆盖历史修改。导入支持 UTF-8、GBK/GB18030，拒绝损坏的 CSV 行和伪装成 CSV 的 XLSX 文件。

已经被旧版程序写成替代符或方框字符的文字无法从这些字符本身还原，需要从未损坏的原始文件重新导入。若新导出文件中的中文编码正确，但特定 Excel 环境仍显示方框，应再检查该环境的中文字体。
